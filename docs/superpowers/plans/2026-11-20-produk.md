# Produk Lengkap (CRUD + Barcode + Foto) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Membangun fitur kelola produk offline-first lengkap (CRUD, barcode scan kamera, foto kamera/galeri, arsip + hapus, sinkron manual ke cloud) yang siap diuji di HP.

**Architecture:** SQLite HP (Drift) sebagai sumber utama; backend Express + Postgres menyimpan salinan per `store_id` (JWT access). Sinkron manual push-then-pull, last-write-wins per baris via millis perangkat, hapus = soft delete tersinkron, file foto dipertahankan sampai purge. State: Riverpod 3 `Notifier`.

**Tech Stack:** Flutter 3.38 / Dart 3.10, Riverpod 3 `Notifier`, GoRouter, Drift 2.31 (pin) + `sqlite3_flutter_libs: 0.5.42` (jangan naik ke eol), Dio, `mobile_scanner`, `image_picker`, `uuid`; Backend Node 24 TS Express + pg + zod; Postgres 18; vitest + supertest; flutter_test.

**Spec:** `docs/superpowers/specs/2026-11-20-produk-design.md`

## Global Constraints

- Android only v1, Flutter.
- Offline-first: semua fitur utama tanpa internet setelah login pertama.
- Local DB: SQLite (Drift 2.31, `sqlite3_flutter_libs: 0.5.42` — jangan 0.6.0+eol).
- Cloud: REST API + PostgreSQL, isolasi via `store_id` dari JWT (jangan percaya `store_id` body).
- 1 user per toko (1 HP = 1 akun pemilik, PIN milik pemilik).
- Lisensi v1: fondasi saja (kolom siap, tanpa enforcement expired).
- Uang INTEGER rupiah, stok tidak boleh minus.
- Barcode wajib via kamera (`mobile_scanner` layar penuh); foto boleh kamera/galeri (`image_picker`).
- Sinkron manual via tombol saja (tanpa auto-sync); full pull tanpa pagination v1.
- Error selalu tampil di UI; tanpa `catch` umum tidak boleh macet loading (pelajaran kasus daftar).
- Drift codegen: `dart run build_runner build --force-jit --delete-conflicting-outputs` (Dart 3.10).
- Anti-goal: tidak ada koneksi langsung HP → PostgreSQL.

## Review Focus

- Barcode duplikat dalam 1 toko ditolak dengan pesan jelas (bukan crash SQLite mentah).
- Foto produk hilang/dihapus dari galeri: detail produk tetap buka dengan placeholder, tidak crash.
- Produk arsip tidak bisa dijual di kasir nanti: disembunyikan dari pencarian (aturan dicatat, kasir plan berikutnya).
- Sinkron saat token access kedaluarsa: refresh lalu lanjut, bukan gagal diam-diam.
- Stok minus via edit produk ditolak dengan pesan (bukan tersimpan 0 diam-diam).
- Setiap baris di atas dipin oleh test di task pemiliknya (lihat langkah test tiap task).
