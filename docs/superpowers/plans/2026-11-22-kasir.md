# Kasir v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Kasir offline-first: keranjang persist, bayar tunai/QRIS/transfer, struk layar, stok atomik, void beraudit, sinkron manual.

**Architecture:** Drift lokal sumber utama (tabel `Sales`, `SaleItems`, `CartLines`); backend Postgres salinan per `store_id` via `GET/POST /api/v1/sales`; nomor struk `<INISIAL><DDMMYYYY><NNNN>` unik per (store, nomor); sinkron push-then-pull reuse pola produk.

**Tech Stack:** Flutter 3.38 + Riverpod 3 + Drift 2.31 (schema v2 → v3); Express + zod + pg; vitest; flutter_test.

**Spec:** `docs/superpowers/specs/2026-11-22-kasir-design.md`

## Global Constraints

- Android only v1; 1 user per toko.
- Offline-first: semua kasir jalan tanpa internet setelah login pertama.
- Uang INTEGER rupiah; waktu millis UTC epoch di HP, timestamptz di server.
- Sinkron manual via tombol saja (tanpa auto-sync).
- Stok tidak boleh minus (tolak dengan pesan).
- Foto produk lokal-only (tidak ikut sync).
- Drift 2.31, sqlite3_flutter_libs 0.5.42, build_runner `--force-jit`.
- Bahasa UI Indonesia.

## Review Focus

- Qty keranjang melebihi stok saat produk dijual di 2 HP bersamaan → pull sync menimpa stok; ekspektasi: stok tidak pernah minus, baris bermasalah ditandai saat validasi bayar.
- Nomor struk duplikat antar HP (satu toko 2 HP) → server 409 unique; ekspektasi: kasir tampilkan "nomor dipakai, buat ulang" bukan crash.
- Void tanpa alasan / alasan kosong → ditolak dengan pesan.
- Produk di keranjang lalu diarsip/dihapus sebelum bayar → baris ditandai bermasalah, bayar diblokir sampai baris dihapus.
- Bayar tunai nominal < total → tombol bayar nonaktif + pesan.
