# Restock v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restock offline-first: catat kulakan multi-produk (qty + harga beli, harga jual opsional), stok atomik, riwayat + batal beraudit, sinkron manual.

**Architecture:** Drift lokal sumber utama (tabel baru `Restocks`, `RestockItems`); backend Postgres salinan per `store_id` via `GET/POST /api/v1/restocks` + `POST /:id/void`; simpan = 1 transaksi DB (insert + stok `+= qty` + update harga); sinkron push-then-pull reuse pola kasir (produk terkait di-push dulu).

**Tech Stack:** Flutter 3.38 + Riverpod 3 + Drift 2.31 (schema v3 → v4); Express + zod + pg; vitest; flutter_test.

**Spec:** `docs/superpowers/specs/2026-11-22-restock-design.md`

## Global Constraints

- Android only v1; 1 user per toko.
- Offline-first: semua restock jalan tanpa internet setelah login pertama.
- Uang INTEGER rupiah; waktu millis UTC epoch di HP, timestamptz di server.
- Sinkron manual via tombol saja (tanpa auto-sync).
- Stok tidak boleh minus (tolak dengan pesan).
- Foto produk lokal-only (tidak ikut sync).
- Drift 2.31, sqlite3_flutter_libs 0.5.42, build_runner `--force-jit`.
- Bahasa UI Indonesia.

## Review Focus

- Batal restock yang stoknya sudah terlanjur terjual sebagian → ditolak 409/StateError, stok tidak berubah, pesan jelas.
- Produk dalam draft lalu diarsip/dihapus sebelum simpan → simpan diblokir dengan pesan, bukan stok hantu.
- Produk sama ditambah 2x dalam satu draft → gabung 1 baris (qty jumlah, harga terakhir menang).
- Harga jual baru di bawah harga beli baru → diizinkan tanpa peringatan (warung kadang banting harga).
- Pull sync menimpa harga katalog yang baru diubah restock lokal → LWW per baris produk tetap berlaku (restock Lokal menandai produk dirty, jadi push menang duluan; pull hanya menang bila server lebih baru).
