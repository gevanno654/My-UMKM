# Laporan Pendapatan Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Layar laporan pendapatan offline (omzet, laba kotor, transaksi, rata-rata struk, chart batang omzet+laba, produk laris, rincian transaksi) dengan laba dari snapshot harga beli saat jual.

**Architecture:** Migrasi skema dulu (Drift v5→v6 + Postgres), lalu alirkan `cost_price` lewat checkout → API → pull, terakhir provider + UI laporan murni baca lokal tanpa mengubah angka stok.

**Tech Stack:** Flutter (Riverpod, GoRouter, Drift 2.31), CustomPainter untuk chart (tanpa dependensi baru bila layak; fallback `fl_chart`), vitest backend.

**Spec:** `docs/superpowers/specs/2026-11-23-laporan-design.md`

## Global Constraints
- Offline-first, isolasi `store_id`, v1 1 user/store, harga snapshot, tolak stok minus.
- Stok HP otoritatif: laporan hanya baca, tidak boleh mengubah stok atau dirty flag.
- Void dikecualikan dari semua angka laporan.
- `flutter test --concurrency 1` hijau + `flutter analyze` bersih tiap commit.

## Review Focus
- Transaksi void masuk angka laporan → harus dikecualikan (ringkasan, chart, laris).
- Ubah harga beli katalog lalu buka laporan lama → laba lama tidak boleh berubah (snapshot).
- Item manual tanpa productId (tanpa cost) → laba item = price × qty, tidak boleh crash/null.
- Periode mingguan di awal/akhir bulan → batas Senin–Minggu presisi, bukan potong tanggal 1.
- Chart 31 pasang batang di HP kecil → scroll horizontal, tidak boleh overflow.
