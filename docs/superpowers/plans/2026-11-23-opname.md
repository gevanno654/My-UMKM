# Stock Opname v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Opname per produk: sesuaikan stok ke hasil hitung fisik + catat selisih beraudit + void beraudit, sinkron manual.

**Architecture:** Drift lokal sumber utama (tabel baru `Adjustments`, schema v4 → v5); backend Postgres salinan per `store_id` via `GET/POST /api/v1/adjustments` + `POST /:id/void`; simpan = 1 transaksi DB (insert adjustment + `SET stock = fisik`); server terapkan diff relatif (`stock += diff`) agar dua HP tidak saling timpa; sinkron push-then-pull reuse pola restock (produk di-push dulu).

**Tech Stack:** Flutter 3.38 + Riverpod 3 + Drift 2.31 (schema v4 → v5); Express + zod + pg; vitest; flutter_test.

**Spec:** `docs/superpowers/specs/2026-11-23-opname-design.md`

## Global Constraints

- Android only v1; 1 user per toko.
- Offline-first: semua opname jalan tanpa internet setelah login pertama.
- Uang INTEGER rupiah; stok INTEGER satuan; waktu millis UTC epoch di HP, timestamptz di server.
- Sinkron manual via tombol saja (tanpa auto-sync).
- Stok tidak boleh minus (tolak dengan pesan).
- Foto produk lokal-only (tidak ikut sync).
- Drift 2.31, sqlite3_flutter_libs 0.5.42, build_runner `--force-jit`.
- Bahasa UI Indonesia.

## Review Focus

- Hasil fisik sama dengan stok sistem (diff 0) → ditolak "tidak ada perubahan", bukan dokumen kosong.
- Hasil fisik membuat stok minus? Tidak mungkin (set absolut ≥ 0); tapi void yang membuat stok < 0 → 409/StateError, stok tidak berubah.
- Produk diarsip/dihapus → tombol Sesuaikan disembunyikan; bila terlanjur dibuka lalu diarsip sebelum simpan → simpan diblokir.
- Retry POST id sama (timeout lalu kirim ulang) → tidak mutasi stok 2x (cek duplikat SEBELUM mutasi).
- Void adjustment yang produknya sudah dihapus → tetap void (status berubah), stok tak kembali (seperti void restock).
